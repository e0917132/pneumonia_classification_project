# 데일리 로그: Mission 0·1 (문제 해결 전략 수립, 데이터 이해 및 Baseline 구축)

**[오늘 목표]**
* 문제 해결 전략을 수립하고, 데이터 구조를 파악하고 Baseline을 구축한다.

**[선택한 방법]**

*Mission 0. 문제 해결 전략 수립 (Baseline 코드 기준)*
* 성능 개선 가설 2개를 귀무가설(H0)과 대립가설(H1)로 세운다.
  * 가설 1 (입력 처리)
    * H0: 비율을 유지하는 전처리를 train과 test에 똑같이 적용해도, 128×128 강제 Resize와 정확도 차이가 없다.
    * H1: 비율을 유지하는 전처리를 train과 test에 똑같이 적용하면 정확도가 높아진다.
  * 가설 2 (모델과 학습)
    * H0: ImageNet 사전학습 모델로 충분히 학습해도, 2층 CNN을 2 epoch 학습한 Baseline과 정확도·AUC 차이가 없다.
    * H1: ImageNet 사전학습 모델로 충분히 학습하면 정확도와 AUC가 높아진다.
  * 검정 방법: 같은 fold 분할에서 두 조건의 예측을 McNemar 검정으로 비교하고, p<0.05이면 H0을 기각한다.
* 전체 흐름: 데이터 구조와 클래스 분포 확인 → 샘플 이미지로 전처리 필요성 확인 → Baseline 학습과 리더보드 점수 기록 → 검증 데이터 분리(Stratified K-Fold) → 전처리와 모델을 단계적으로 바꾸며 실험 → 최고 모델로 제출하고 기록 → 결과 분석(실패 케이스, Grad-CAM)
* 평가 지표: 공식 지표는 Accuracy(목표 0.98 이상), 보조 지표는 ROC-AUC와 클래스별 정밀도·재현율·F1. 판정 임계값은 0.5로 고정한다.

*Mission 1. 데이터 이해 및 Baseline 구축*
* 해커톤 제공 Baseline 코드(2층 CNN)를 그대로 실행해 기준선을 만든다.
* 전처리: 흑백 변환 후 128×128 Resize, Tensor 변환 (정규화와 증강 없음)
* 모델: 합성곱 2층(16 → 32 채널, ReLU + MaxPool) → Flatten → 완전연결층(32×32×32 → 2)
* 학습: Adam(lr 1e-3), batch 32, 2 epoch, 검증 없음
* 데이터 확인: 클래스 분포, 샘플 이미지, 원본 이미지 크기와 letterbox 여부 확인

**[선택 이유]**
* 데이터 구조를 먼저 확인해 전처리 필요성을 파악하고, Baseline 점수를 기준값으로 기록한 뒤 검증 체계를 만들고 전처리와 모델을 단계적으로 바꾸는 순서로 흐름을 설계했다. 검증 없이 바꾸면 무엇이 효과를 냈는지 판단할 수 없기 때문이다.
* Accuracy는 대회 채점 기준이라 목표 지표로 정했다. 다만 PNEUMONIA가 74%인 불균형 데이터라서 PNEUMONIA만 예측해도 약 74%가 나온다. 그래서 임계값과 무관한 AUC와 클래스별 지표를 함께 보기로 했다.
* 검증 체계를 가장 먼저 만들고 그다음 전처리를 개선하기로 했다. 입력이 왜곡된 상태에서는 모델을 바꿔도 공정하게 비교하기 어렵다.
* 실험 결과는 같은 fold 분할과 seed의 OOF 정확도·AUC로 비교하고, 차이가 우연인지 McNemar 검정으로 확인한다. test 데이터는 제출 파일 생성에만 쓴다.
* 개선의 출발점이 되는 기준선이 필요하다. 해커톤에서 제공한 Baseline을 그대로 실행해야 이후 개선 효과를 같은 기준으로 비교할 수 있다.
* 코드 구조와 데이터 형태를 먼저 이해해야 Baseline의 한계와 개선 방향을 근거 있게 정할 수 있다.

**[결과]**

| 항목 | 값 |
|---|---|
| 학습 loss | epoch 1: 0.2225, epoch 2: 0.1167 |
| 검증 점수 | 측정 안 됨 (검증 없음) |
| 리더보드 점수 | 0.75 |
| 맞힌 장수 (624장 중) | 약 468 |
| test 예측 분포 | NORMAL 358장(57%), PNEUMONIA 266장(43%) |
| train 라벨 분포 | NORMAL 1,341장(25.7%), PNEUMONIA 3,875장(74.3%) |

* 이 단계가 기준선이므로 Before 값은 없다. 이후 실험은 이 리더보드 점수 0.75를 기준으로 비교한다.
* 예측 분포가 train 분포와 크게 다르다. NORMAL을 실제보다 많이 예측했다.
* 데이터 확인 결과 train은 모두 224×224 letterbox 형태(위·아래 검은 여백)이고, test는 원본 해상도가 제각각이며 여백이 없다.

**[달성도]**
* 문제 해결 전략 수립: **성공** (가설 2개, 전체 흐름, 평가 지표 정의)
* 데이터 구조 파악과 Baseline 구축: **성공** (코드 실행, 제출 파일 생성, 리더보드 점수 확인)
* 리더보드 점수 0.98 목표 대비: 0.75 → **미달** (목표 대비 약 77%, 약 0.23 부족)

**[인사이트]**
* Baseline 코드를 보고 예상한 다섯 가지 문제(검증 없음, 비율 왜곡, 과소적합, 클래스 불균형 미고려, 정규화·증강 부재) 중 클래스 불균형(74:26)과 입력 비율 차이(train letterbox, test 원본)는 데이터 확인에서 실제로 확인되었다.
* 검증 없이 제출한 모델은 성능을 알 수 없다. 리더보드 점수 하나로만 판단하게 된다.
* 라벨 비율이 74:26이라서, PNEUMONIA만 예측해도 정확도가 약 74%다. Baseline 0.75는 이 수준과 거의 같아서 모델이 학습했는지 정확도만으로는 알 수 없다.
* 128×128 강제 Resize는 흉곽 비율을 왜곡한다. 원본 이미지 크기가 제각각인 test에 같은 처리를 하면 train과 입력 형태가 달라진다.
* 제공된 노트북에는 실행을 막는 문법 오류(테스트 데이터 경로 셀)와 현재 폴더에 의존하는 경로가 있었다. 경로를 자동으로 찾도록 고친 뒤 실행할 수 있었다. 노트북 실행 전에 경로와 문법을 확인해야 한다.
